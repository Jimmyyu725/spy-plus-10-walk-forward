# SPY Plus 10 Walk-Forward 设计规范

## 1. 研究目标与不可更改的判定标准

本项目在 QuantConnect 纯云端环境中研究一套 `Benchmark-Plus-Alpha` 组合。初始资金为 `1,000,000 USD`，评价区间为 `2015-01-01` 至完整组合、全部已启用模块与 SPY 基准共同具备数据的最新完整交易日。

每个自然年独立计算策略和 SPY 的含分红总回报。该年仅在下式成立时通过：

`strategy_return >= spy_total_return + 0.10`

这里的 `0.10` 是 10 个百分点，不是相对提高 10%。例如，SPY 为 `-10%` 时门槛为 `0%`，SPY 为 `+10%` 时门槛为 `+20%`。2015 年至最后一个完整自然年逐年判定；当前未结束年份以相同起点和共同截止日计算 YTD，并仍使用 10 个百分点门槛，但必须标记为 `PARTIAL_YEAR`。

正式结论只有三种：

- `PASS`：所有完整年份和当前部分年份均通过，且数据、前视、成本、风险和复算门禁全部通过。
- `FAIL`：至少一个可验证年份未达到收益门槛，或违反风险限制。
- `UNVERIFIED`：数据、许可、编译、成交、复算或审计证据不足，不能发布通过或失败结论。

累计收益、CAGR 或少数表现最好的年份不能替代逐年门槛。若策略失败，报告必须保留失败年份，不能删除年份、修改基准或把目标改成累计跑赢。

## 2. 诚实性边界

策略在 2026 年设计，因此 2015 年以后只能称为“无未来数据的历史 walk-forward 模拟”，不能冒充当年已经预注册的真实样本外业绩，也不能保证未来收益。

本规范、资产池、信号公式、参数、风险上限和成本模型必须在第一次正式 `2015–最新` 回测之前冻结并提交。正式回测后：

- 不得根据失败年份修改参数后仍把新结果称为本轮样本外验证；
- 任何新假设必须成为独立版本，保留旧版本及其失败结果；
- 不得使用当前指数成分股倒推历史，不得选择回测期间表现最好的幸存标的；
- 不得使用未来发布的财报、宏观修订值、未完成价格条或未来合约信息；
- 不得用最终年度结果、相对 SPY 的年内差距或临近年末的达标缺口调整风险。

年度 `SPY+10` 只用于评价，不作为追赶式加仓信号，避免在落后时被动赌博。

## 3. 执行架构

项目分为两个环境：

1. **Atlas 控制面**：保存 Git 源码和规范，运行 LEAN CLI、静态检查和只使用人工夹具的轻量单元测试。Atlas 不保存或下载完整历史行情，也不运行本地 LEAN Docker 回测。
2. **QuantConnect Cloud 数据面**：R1-4 Research Node 用于数据覆盖与特征审计；B2-8 Backtest Node 用于编译、完整历史回测和结果生成。

标准流程为：

`本地规范/代码 -> Git 检查点 -> LEAN CLI 推送 -> 云端编译 -> 云端回测 -> 结果下载 -> 独立复算 -> 报告归档`

QuantConnect API 凭据保存在用户级 LEAN 凭据目录，不写入策略源码。项目不配置实时节点、券商账户或实盘权限。

## 4. 组合结构

采用 `SPY Beta Core + Independent Alpha Sleeves`，因为目标是逐年相对 SPY 增加 10 个百分点，而不是脱离基准追求绝对收益。

### 4.1 SPY Beta Core

- 目标 SPY Beta 为 `1.00`，允许范围为 `0.80–1.20`。
- 核心优先使用 SPY 现货；现金、保证金和 Alpha 对冲造成的偏差由 ES/MES 调整。
- SPY 分红计入策略和基准总回报，二者使用相同交易日与估值口径。
- 风险削减只能减少 Alpha，不因短期预测主动清空核心 SPY，以免把组合变成战术择时策略。

### 4.2 Equity Factor Alpha

- 使用 QuantConnect 历史时点美国股票 Universe，不使用今天的固定成分股名单。
- 每月最后一个完整交易日生成排名，下一交易日开盘后成交。
- 候选必须满足：价格至少 `5 USD`、过去 20 个交易日日均美元成交额位于 Universe 前 500、至少 252 个交易日价格历史、当时可获得的基本面记录完整。
- 12-1 月动量定义为从第 252 个交易日前收盘到第 21 个交易日前收盘的总回报。
- 质量分数固定为当时已发布数据计算的 `50% ROE + 50% gross-profit-to-assets`；两个分项分别在当期横截面内标准化。
- 低残差波动率使用过去 126 个交易日个股对 SPY 日收益的一元回归残差年化标准差，并取负值作为“越低越好”的分数。
- 固定复合排名为：`50%` 的 12-1 月动量、`25%` 的质量分数、`25%` 的低残差波动率。所有分项先在当期横截面内 winsorize 到 1%/99%，再转为 z-score；不足窗口的股票不进入候选。
- 持有排名最高的 30 只股票，等风险配置；不卖空个股。使用 ES/MES 或 SPY 空头对冲当期估计 Beta，使该模块目标 Beta 为 0。
- 模块目标年化波动率为 `5%`，总名义敞口不得超过组合净值的 `50%`。

若所需 point-in-time 基本面数据需要付费许可，回测在购买前停止并列出许可；不能静默删掉质量指标或用当前基本面替代。

### 4.3 Multi-Asset Trend Alpha

- 固定根合约为：股指 `ES、NQ`，国债 `ZN、ZB`，商品 `GC、SI、CL、NG、ZC、ZS`，外汇 `6E、6J、6B`。只使用 QuantConnect Security Master 可按历史时点映射且当时可交易的实际合约。
- 每周最后一个完整交易日计算 `3、6、12` 个月超额收益方向，三者等权形成趋势分数；下一交易日执行。
- 单合约按过去 60 个交易日实现波动率的倒数定仓，组合按过去 252 个交易日协方差估计缩放。
- 换月使用固定的成交量优先规则，并在实际合约上成交；连续合约只用于信号，不作为可成交证券。
- 模块目标年化波动率为 `7%`，总名义敞口不得超过组合净值的 `70%`。

趋势信号收益和波动率缩放收益必须分别报告，另运行“只有波动率缩放、没有趋势方向”的对照，防止把仓位缩放误称为趋势 Alpha。

### 4.4 Defined-Risk Option Alpha

- 仅使用 SPY 期权，按真实历史合约、到期日、行权价、报价和合约乘数成交。
- 每周第一个完整交易日收盘后评估一次，最早在下一交易日 `10:00 ET` 使用当时的分钟报价建立 30–60 DTE 的 SPY 牛市看跌价差；所有腿必须同时具备有效买卖价。
- 入场条件固定为：SPY 收盘高于过去 200 个交易日简单均线，且最接近 45 DTE 的平值隐含波动率比过去 20 个交易日实现波动率高至少 5 个年化波动率百分点。
- 在合格到期日中选择 Delta 最接近 `-0.20` 的 put 作为空头腿，选择同到期日 Delta 最接近 `-0.10` 的 put 作为多头腿。若无法唯一选择，按到期日更近、持仓量更高、行权价更低的顺序打破平局。
- 价差在获得最大信用额的 50% 时止盈，在剩余 21 DTE 时退出；若没有更早退出，则持有至 21 DTE 的下一个可交易时点。止损由价差最大损失和组合级预算共同限定，不使用无限损失订单。
- 不允许裸卖期权，不允许无限损失结构，不允许使用回测结束后才知道的到期结算信息。
- 单次最大保费或最大结构损失不得超过组合净值的 `0.50%`，滚动 12 个月期权损失预算不得超过 `3%`。
- 当买卖价差超过中间价的 `20%`、任一腿无有效 bid、成交量和持仓量门槛不满足或保证金模型无法确定最大损失时，不成交并记录原因。
- 该模块目标年化波动率为 `3%`，总名义风险不得突破组合级上限。

期权规则在第一次正式回测前固定；不能在看到某次崩盘后再选择当时最有利的执行价或期限。

## 5. 组合风险与资金约束

- 组合目标年化波动率：`18%`。
- 总名义杠杆上限：`2.00x`；Alpha 层合计名义敞口上限：`1.00x`。
- 任一 Alpha 模块的预测风险贡献不得超过 Alpha 总风险的 `40%`。
- 组合预测 Beta 必须保持在 `0.80–1.20`。
- 组合从历史最高权益回撤达到 `15%` 时，所有 Alpha 目标风险减半；达到 `25%` 时，Alpha 目标敞口设为 0，并在下一可交易时点开始有序平仓，只保留核心 Beta 维护和无法立即退出的定义风险期权处理。
- 任何时点不得触发保证金追缴；若回测发生强制平仓、负可用保证金或超过杠杆上限，结果为 `FAIL`。
- 不使用未来相关性或全年波动率。所有风险估计仅使用当前时间之前的已完成数据。

风险限制不能在某个历史年份结束后调整，也不能因临近年度目标而放宽。

## 6. 数据与防作弊门禁

- 股票使用 QuantConnect US Equity Security Master 的历史公司行动、退市和代码映射。
- 股票 Universe、基本面和可交易状态必须为 point-in-time；若数据不是 point-in-time，必须使用预先写入规范的发布滞后，否则禁止使用。
- 期货使用实际合约和当时可见的 Future Universe；信号、换月和成交时间分离。
- 期权使用当时真实存在的 Option Chain；不得从未来链反推历史合约。
- 加密货币保留为后续独立 Alpha 版本，不进入首个冻结版本，避免用其 2015 年后的极端赢家结果污染首次验证。
- 价格信号只读取已完成的日线；收盘后生成的信号最早在下一交易日成交。
- 财报和宏观数据按原始发布日期进入，禁止使用最终修订值提前回填。
- 统一预热期从 `2012-01-01` 开始。2015 年之前只用于初始化固定公式所需的历史窗口和验证数据可用性，不搜索 2015 年后的最佳参数。
- 任一核心数据缺失、时间倒退、重复、非正价格、公司行动无法解释或许可不可验证时，结果为 `UNVERIFIED`。

第一次正式回测必须保存代码提交、云端项目 ID、回测 ID、数据集清单、许可状态、起止日期和生成时间。QuantConnect 托管数据无法导出完整原始哈希时，保存平台返回的项目、回测和数据版本标识作为可获得的最强证据。

## 7. 成交、费用与现实建模

策略和 SPY 基准使用同一估值日期和总回报口径。费用按资产类别分别建模：

- 股票与 ETF：每股 `0.005 USD`、每笔最低 `1 USD` 的佣金底线，加 QuantConnect 可用的监管费；成交价另计有效买卖价差的一半和最小 `5 bps` 不利滑点，取两者较大值。
- 期货：每张合约每边 `2.50 USD` 的费用底线，加至少 1 tick 不利滑点；换月两边都计成本。
- 期权：每张合约每边 `0.65 USD`、每笔最低 `1 USD` 的费用底线，加 QuantConnect 可用的监管费；买入按 `mid + 25% spread`、卖出按 `mid - 25% spread`，并服从最小 tick。多腿结构每条腿分别收费和滑点。
- SPY 基准在 2015 年首个共同交易日建立头寸并持有，计入首次成交成本；期末不假设免费强制清仓，另报告假设清仓敏感性。

正式结果至少提供基础成本和双倍滑点压力测试。税费不计入，报告必须明确说明。

## 8. 软件组件与接口边界

实现拆分为以下可独立审计的模块：

1. `universe.py`：只负责历史时点标的选择和可交易性过滤。
2. `signals/`：分别计算 Equity Factor、Futures Trend 和 Option 信号，不访问未来账户状态。
3. `risk.py`：把模块信号转换为受 Beta、波动率、杠杆、风险贡献和回撤限制约束的目标。
4. `execution.py`：处理实际合约选择、换月、价差、手续费、滑点和订单生命周期，不决定信号方向。
5. `benchmark.py`：生成独立 SPY 含分红买入持有基准。
6. `audit.py`：记录每个信号的数据截止时间、输入摘要、目标、订单和风险状态。
7. `metrics.py`：从权益序列独立计算逐年收益及 `SPY+10` 门禁。
8. `main.py`：只负责 QuantConnect 生命周期和模块编排。

核心数据流为：

`Point-in-time Cloud Data -> Universe -> Signals -> Risk Constraints -> Next Tradable Execution -> Portfolio Ledger -> Annual Gate -> Audit Report`

模块之间使用明确的数据对象传递，不允许报告器重新计算或覆盖交易信号。

## 9. 错误处理与失败关闭

- 云端编译失败、节点超时或 API 认证失败时，不生成正式绩效结论。
- 许可缺失时输出所需数据集和费用页面，停止在购买前。
- 核心 SPY 数据或任一已持仓证券数据缺失时停止；不得向前填充价格后继续成交。
- Option Chain 正常但没有满足预先过滤条件的合约属于合法空仓；整个链缺失、报价异常或无法区分二者时为 `UNVERIFIED`。
- 订单拒绝、部分成交、到期、行权、指派和强制平仓必须显式进入组合账本。
- 现金、保证金、持仓、手续费和权益不守恒时立即失败。
- 报告的 `PASS/FAIL/UNVERIFIED` 必须由结构化门禁字段生成，不能手写覆盖。

## 10. 测试与验证

### 10.1 本地轻量测试

仅使用人工构造的价格、时间戳、期权链和合约夹具，验证：

- 百分点门槛计算，包括 `SPY -10% -> 0%` 和 `SPY +10% -> 20%`；
- 完整年份与当前部分年份的边界；
- 信号只能影响下一可交易时点；
- 修改未来数据不会改变过去的 Universe、信号、订单或权益；
- z-score、动量、质量、残差波动率、趋势分数和波动率缩放；
- Beta 对冲、风险贡献、2.00x 杠杆、15%/25% 回撤门禁；
- 期货换月、期权多腿最大损失、费用和不利滑点；
- 账本现金、保证金和权益守恒。

### 10.2 云端验证

- 单独运行三个 Alpha 模块、SPY 核心和完整组合，报告边际贡献而不是只展示最终组合。
- 运行无趋势方向但保留波动率缩放的 Futures 对照。
- 运行基础成本和双倍滑点压力测试。
- 逐年输出策略收益、SPY 总回报、百分点差、门槛和状态。
- 输出最大回撤、年化波动率、Sharpe、Sortino、Calmar、Beta、Alpha、跟踪误差、换手率、成本、最大保证金占用和杠杆峰值。
- 用独立代码路径从每日权益重新计算逐年收益、最大回撤和年度门禁，容差不超过 `0.01` 个百分点。
- 抽查至少 10 个历史信号，证明输入发布时间、信号时间、订单时间和成交时间严格递增。

## 11. 验收与交付物

首个冻结版本完成必须同时具备：

- QuantConnect 云端项目 `SPY Plus 10 Walk-Forward`；
- Atlas 私有 Git 项目及可回退提交；
- LEAN CLI 成功登录并能读取正确组织；
- 模块化 Python 源码及人工夹具测试；
- 2015 至最新共同日期的第一次冻结回测；
- 云端项目 ID、回测 ID、参数、数据许可和代码提交记录；
- 每日权益、交易、持仓、风险、费用和信号审计文件；
- 中文总结和逐年 `PASS/FAIL/UNVERIFIED` 表；
- 第一次正式结果无论成功或失败都提交归档。

只有所有年份通过且审计门禁完整时，才可以说“这次历史模拟逐年达到 SPY+10 个百分点”。不得把该结论表述为未来保证。

## 12. 分阶段实施边界

本设计是单一项目的总规范，但实现必须拆成五个可独立审查的里程碑，不能在一个不可审查的大改动中完成：

1. **Cloud Foundation**：LEAN CLI 登录、组织 workspace、云端项目、Git 私有备份和最小云端编译。
2. **Audit Baseline**：SPY 基准、年度门槛、账本、成本、审计记录和人工夹具测试。
3. **Alpha Modules**：依次实现 Futures Trend、Equity Factor、Defined-Risk Option，每个模块先独立编译和回测。
4. **Portfolio Integration**：组合风险、Beta、杠杆、回撤和模块间资金协调。
5. **Frozen Evaluation**：提交冻结版本后只运行一次主 `2015–最新` 评价，完成独立复算和结果归档。

每个里程碑都需要独立实施计划、测试证据和 Git 检查点。前一里程碑不通过时不得跳到最终回测。

## 13. 明确不包含的范围

- 连接 Webull、Robinhood、IBKR 或其他券商；
- 模拟盘、实盘、自动下单或实时节点；
- 根据正式回测失败年份继续寻优并覆盖失败结果；
- 裸卖期权、无限损失结构或超过 2.00x 名义杠杆；
- 把当前幸存股票、未来指数成分、修订后宏观数据或未来期权链用于历史决策；
- 在未经用户确认前购买任何额外数据许可或计算资源。
