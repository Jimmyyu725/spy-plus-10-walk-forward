# SPY Plus 10 v2 Robust Alpha 设计规范

## 1. 状态、目的与版本边界

本规范定义独立的 `v2` 研究版本。它不修改、不删除、不覆盖 v1 的设计、代码、云端回测或失败结果。

v1 的冻结代码提交为 `66b630342c3171cb30c8f05faa7cac69706e35f6`。QuantConnect 基础成本回测和双倍滑点回测均完成；平台结构化统计显示 2015 至 2026 年的 12 个评价期全部未达到 `SPY + 10`，而每日证据写入失败使正式证据状态为 `UNVERIFIED`。v2 必须保留这些事实，不能把新结果冒充 v1 的替代结果。

v2 的目标从“只接受每年 SPY+10”改成双层目标：以可验证的长期净超额和回撤控制作为主要验收标准，同时继续逐年报告 `SPY+10` 挑战指标。v2 仍然禁止未来数据、幸存者偏差、最终年份挑选、追赶式加杠杆和正式结果后的覆盖式调参。

v2 使用新的 QuantConnect 项目 `SPY Plus 10 Walk-Forward v2` 和新的本地云端目录。v1 项目与代码路径只读保留。项目不包含实盘节点、券商连接或真实下单。

Atlas 使用已归档的 QuantConnect 订单和已平仓交易按订单标签做诊断性归因。以下数值扣除了对应交易记录的费用，但不包括期末未实现损益，因此只用于判断改造方向，不作为完整组合收益归因：

| 模块 | 基础成本已平仓净结果 | 双倍滑点已平仓净结果 | v2 决策 |
|---|---:|---:|---|
| SPY 核心及组合对冲 | 约 `+2,146,489 USD` | 约 `+2,107,041 USD` | 保留，但增加事前动态风险控制 |
| 股票因子 | 约 `+181,383 USD` | 约 `+163,818 USD` | 保留并重建为更独立的横截面 Alpha |
| 期货趋势 | 约 `-14,235 USD` | 约 `-25,038 USD` | 淘汰 v1 信号，重新设计趋势加 carry |
| 定义风险期权 | 约 `-5,559 USD` | 约 `-6,934 USD` | 停止作为收益 Alpha，改成有预算的防御模块 |

v1 基础成本累计回报约 `325.34%`，SPY 同口径累计总回报约 `274.29%`，但逐年超额通常只有 `0–3` 个百分点，且最大回撤约 `33.6%`。这说明 v1 主要是 SPY Beta 加弱 Alpha；增加同类杠杆不能解决 Alpha 强度和回撤问题。

## 3. 不可更改的 v2 验收目标

### 3.1 基础成本主要目标

把所有下一期执行折拼接成一条 walk-forward 权益曲线后，必须同时满足：

1. 策略净 CAGR 至少比 SPY 含分红总回报 CAGR 高 `3.00` 个百分点；
2. 完整评价自然年中至少 `75%` 的年份取得正超额收益；比例向上取整，2015–2025 共 11 个完整年份时至少需要 9 年；
3. 日度主动收益的 Information Ratio 不低于 `0.50`；
4. 最大回撤不超过 `20.00%`；
5. 任一时点总名义杠杆不超过 `2.00x`，Alpha gross 不超过 `0.80x`；
6. 保证金追缴、保证金警告、无效订单、裸期权腿、无限损失结构和未来数据计数均为 0；
7. 数据许可、时间因果、成本、账本、证据保存和独立复算全部为 `PASS`。

当前未结束年份继续输出部分年份收益，但不进入“完整年份正超额比例”的分母。它仍进入累计 CAGR、最大回撤和风险门禁。

独立 SPY 基准在 2015 年首个共同交易日以同一初始权益建立一次含分红总回报头寸，此后连续持有，不按年度重置。策略和基准都使用共同估值日期；基准计入首次成交成本，并单独报告期末假设清仓成本。Information Ratio 固定为日度主动收益均值除以日度主动收益标准差，再乘 `sqrt(252)`；主动收益标准差为 0 时结果为 `UNVERIFIED`。

### 3.2 双倍滑点压力目标

同一代码提交、同一 walk-forward 决策和同一交易路径逻辑在 `2x` 不利滑点下必须满足：

1. 策略净 CAGR 至少比 SPY 高 `2.00` 个百分点；
2. 最大回撤不超过 `22.00%`；
3. 总杠杆、保证金、订单、数据和独立复算门禁与基础成本相同。

双倍滑点不得重新训练或重新选择更有利参数；它只替换滑点倍数。若价格变化自然导致后续持仓或订单路径变化，必须在报告中解释。

### 3.3 挑战指标

每个完整年份和当前部分年份继续计算：

`strategy_return >= spy_total_return + 0.10`

这里的 `0.10` 仍是 10 个百分点。挑战指标逐年报告 `PASS/FAIL`，但不进入 v2 主要验收状态，也不得用于年内追赶、风险放大、参数选择或临近年末的仓位调整。

## 4. 研究数据与 walk-forward 边界

### 4.1 历史身份

v2 在 2026 年、且在已经看过 v1 的 2015–2026 结果后设计。因此任何 v2 历史结果只能称为“研究型 walk-forward 模拟”，不能称为当时预注册的真实样本外业绩。

真正未被本项目观察的新样本外证据只能来自 v2 锁定后的 paper-forward 数据。paper-forward 至少运行 6 个月；若用户以后明确授权实盘，仍需另建审批和上线规范，本规范不提供该授权。

### 4.2 固定时间折

- 数据和指标预热：`2008-01-01` 开始；
- 第一个训练窗：`2010-01-01` 至 `2014-12-31`；
- 第一个执行折：2015 年首个共同交易日至 2015 年最后一个共同交易日；
- 后续每个自然年使用紧邻其前的 5 个完整自然年训练，仅在下一年执行；
- 2026 折使用 `2021-01-01` 至 `2025-12-31` 训练，并执行到固定的最新完整共同交易日；
- 所有决策使用已完成数据，年末训练结果最早在下一年首个可交易时点生效；
- 任一训练窗缺失完整 5 年核心数据时，该执行折为 `UNVERIFIED`，不得缩短窗口后继续。

组合资金、持仓、历史高点和账本从 2015 年首个执行折连续传递到下一折，不能在年初重置。折的作用只是在固定时间更新三个风险参数。

训练过程只选择预先定义的风险预算，不选择资产、因子、年份或成本假设。信号公式和候选资产池在第一次 v2 完整 walk-forward 前冻结。

### 4.3 参数搜索上限和选择规则

v2 只允许三个全局经济参数维度，共 27 个组合：

| 参数 | 固定候选值 |
|---|---|
| SPY 核心年化波动率目标 | `10%`, `12%`, `14%` |
| 股票 Alpha gross 上限 | `0.40x`, `0.50x`, `0.60x` |
| 期货 Alpha 年化波动率目标 | `4%`, `6%`, `8%` |

每个训练窗按以下固定顺序选择：

1. 淘汰任何数据、因果、保证金、杠杆或账本门禁失败的组合；
2. 淘汰训练窗最大回撤超过 `20%` 的组合；
3. 淘汰完整训练年份正超额比例低于 `60%` 的组合；
4. 计算各组合的训练年度超额收益中位数；
5. 保留距离最高中位数不超过 `0.50` 个百分点的组合；
6. 在保留组合中选择总换手率最低者；
7. 若仍并列，依次选择更低期货波动目标、更低股票 gross、更低 SPY 波动目标。

若没有组合通过前三项，下一执行折只运行风险管理后的 SPY 核心，Alpha 目标为 0，并记录 `NO_ELIGIBLE_TRAINING_CONFIGURATION`。不能放宽门槛寻找一个赢家。

QuantConnect Cloud 的原生优化只用于调度固定 27 个组合。Atlas 独立读取每个训练回测的结构化证据并执行上述选择，不能用人工观察曲线替换机械选择器。

## 5. v2 组合架构

v2 由四部分组成：动态 SPY 核心、股票横截面 Alpha、期货趋势加 carry Alpha、定义风险防御期权。只有前三部分贡献常规目标风险；期权模块只使用年度保护预算。

数据流固定为：

`Point-in-time data -> completed-data features -> frozen signals -> walk-forward risk parameters -> portfolio constraints -> next tradable execution -> sleeve ledger -> combined ledger -> evidence chunks -> independent verifier`

所有模块返回目标风险或目标持仓，不得直接清算其他模块。组合协调器是唯一允许执行跨模块风险缩放的组件。

## 6. 动态 SPY 核心

### 6.1 目标 Beta

核心使用 SPY 现货，必要时使用 ES/MES 做小额 Beta 修正。每周最后一个完整交易日，用已完成的 63 日 SPY 日收益计算年化实现波动率：

`raw_beta = selected_spy_volatility_target / realized_volatility_63d`

`raw_beta` 截断到 `[0.50, 1.05]`。若 SPY 最近完整收盘低于此前 200 个完整交易日简单移动平均，目标 Beta 再乘 `0.75`，最终仍截断到 `[0.50, 1.05]`。信号最早在下一交易日常规时段成交。

该规则只能使用价格和已经由训练折选定的波动率目标。不得使用当前年度相对 SPY 的输赢、宏观最终修订值、未来 VIX、年度目标缺口或人工判断。

### 6.2 组合回撤状态

- 组合从历史最高权益回撤达到 `10%`：股票与期货 Alpha 目标各乘 `0.50`；
- 达到 `15%`：股票与期货 Alpha 目标为 0，SPY 核心仍按上述事前规则运行；
- 恢复到距离历史高点不足 `8%`：Alpha 目标恢复到 `0.50`；
- 创出新高后：Alpha 目标恢复到 `1.00`。

状态变化在下一可交易时点执行。回撤规则不能保证事后最大回撤一定小于 20%；`20%` 是必须通过的评价门槛，不是允许放宽的参数。

## 7. 股票横截面 Alpha

### 7.1 数据和 Universe

- 使用 QuantConnect 历史时点 US Equity Universe、Security Master、公司行动、退市和当时可获得的基本面；
- 价格至少 `5 USD`；
- 过去 20 个完整交易日日均美元成交额位于当期 Universe 前 1,000；
- 至少 252 个完整交易日价格历史；
- 因子字段必须按当时发布日期可用，缺失值不插补；
- 每月最后一个完整交易日计算，下一交易日开盘 30 分钟后执行。

### 7.2 固定因子

每个因子先在当期横截面内按 1%/99% winsorize，再转为 z-score：

1. 残差动量：个股过去 252 至 21 个交易日相对 SPY 的回归残差累计收益；
2. 质量：ROE、gross-profit-to-assets 和低应计项三个 z-score 等权；
3. 价值：earnings yield 与 book-to-market 两个 z-score 等权；
4. 低残差风险：过去 126 个完整交易日相对 SPY 回归残差年化波动率的负值。

最终得分为四个因子等权。因子权重不是优化参数，也不得按训练折选择单一历史赢家。

### 7.3 行业、规模和 Beta 中性

数据审计阶段先验证历史时点借券可用性和借券费用：

- 若点时点借券数据在所有训练折和执行折均可用，固定采用同一行业内最高分 40 只做多、最低分 40 只做空；
- 若点时点借券数据不可完整验证，在第一次经济回测前固定切换到同一行业内最高分 40 只做多，并使用行业 ETF 与 SPY/ES 组合对冲行业和市场 Beta；此后不得根据收益在两种结构间切换。

多空结构或回退结构都必须：

- 对行业净敞口做零目标约束；
- 对市值对数暴露做零目标约束；
- 事前 Beta 绝对值不超过 `0.05`；
- 单一股票绝对权重不超过股票模块 gross 的 `3%`；
- 使用训练折选定的模块 gross 上限；
- 建模佣金、监管费、买卖价差、滑点以及适用的借券费用。

## 8. 期货趋势加 carry Alpha

### 8.1 固定候选根合约

固定 Universe，不按最终收益删减：

- 股指：`ES`, `NQ`, `RTY`；
- 国债：`ZT`, `ZF`, `ZN`, `ZB`；
- 外汇：`6E`, `6J`, `6B`, `6A`, `6C`, `6S`；
- 金属与能源：`GC`, `SI`, `HG`, `CL`, `NG`, `RB`, `HO`；
- 农产品与牲畜：`ZC`, `ZW`, `ZS`, `LE`。

数据审计只按可交易历史、有效实际合约映射、成交量和最小合约可承受性排除根合约，不能按收益排除。排除原因和时间覆盖必须在第一次经济回测前冻结。

一个根合约只有在 2010 年至固定研究截止日的计划周度信号日期中，至少 `95%` 的日期具备完整信号历史、两个有效 carry 合约和可交易实际合约，且按 100 万美元组合能够持有最小 1 张而不突破单根风险上限时才合格。覆盖率按日期计数，不能用高收益日期加权；低于门槛的根合约在查看其收益前排除并记录。

### 8.2 固定信号

每周最后一个完整交易日计算三个等权分量：

1. 快速趋势：21 日和 63 日超额收益方向等权；
2. 慢速趋势：126 日和 252 日超额收益方向等权；
3. carry：当时可见近月和次近月实际合约的年化期限结构方向，避开交割和最后交易日缓冲区。

三个分量均截断到 `[-1, 1]` 后等权。连续合约只用于价格信号；carry、换月和订单必须使用当时真实存在的实际合约。信号产生后最早在下一交易日执行。

每个根合约使用 60 日实现波动率倒数定仓，组合使用过去 252 日协方差做风险缩放。模块使用训练折选定的 `4%/6%/8%` 年化波动率目标，总 gross 上限 `0.50x`，单一根合约预测风险贡献不超过模块风险的 `15%`。

## 9. 定义风险防御期权

期权不再被称为 Alpha。它只在事前防御条件触发时购买有限风险保护：

- 标的仅为 SPY；
- 每月首个完整交易日收盘后评估，最早在下一交易日 `10:00 ET` 入场；
- 条件为 SPY 低于此前 200 日均线，或 20 日实现波动率高于此前 756 个完整交易日的 80% 历史分位；
- 选择 60–90 DTE，同到期日的 put debit spread；长 put 目标 Delta `-0.30`，短 put 目标 Delta `-0.10`；
- 两腿必须具备有效 bid/ask、成交量、持仓量和有限最大损失；
- 同时最多一组价差；
- 单次最大支出不超过组合权益 `0.35%`，滚动 12 个月保护成本不超过 `1.50%`；
- 剩余 30 DTE、价差达到最大价值的 80%，或防御条件连续 10 个完整交易日消失时退出；
- 所有腿使用原子组合订单，分别计费和不利滑点；禁止裸腿和无限损失结构。

保护预算和条件不是优化参数。模块的评价是减少组合尾部回撤和对 CAGR 的成本，不要求自身盈利。

## 10. 组合风险与执行

- 组合协调器先应用各模块目标，再应用 walk-forward 参数、回撤状态、Alpha gross `0.80x` 和总 gross `2.00x` 上限；
- 股票与期货预测风险贡献各不得超过 Alpha 总风险的 `60%`；
- 现金、保证金和期权最大损失必须在发单前验证；
- 日内风险削减只能减少现有目标，不能重新计算当日信号或重新选约；
- 股票和 ETF 费用、期货费用、期权费用及监管费沿用 v1 的保守模型；
- 基础成本与双倍滑点只改变滑点倍数，不能改变佣金、信号、训练折或参数选择；
- 税费不计入，并在报告中明确说明；
- 任一保证金追缴、强制平仓、负可用保证金、gross 越界或账本不守恒使该运行 `FAIL`。

## 11. 精确证据系统

### 11.1 写入能力门禁

在任何 v2 经济回测前，运行只包含证据功能的云端 smoke：

1. 保存并读回 1 KB UTF-8 字符串；
2. 保存并读回 1 KB bytes；
3. 用 QuantConnect Object Store list/get API 从 Atlas 获取两个对象；
4. 比对长度与 SHA-256；
5. 保存组织、项目、编译、回测、键名、权限和存储使用量。

若字符串和 bytes 都失败，检查 Storage Create 权限和 Object Store 剩余容量。未经用户明确确认不得购买额外容量。若字符串成功而 bytes 失败，正式证据使用 base64 编码的 gzip 字符串；不能静默跳过证据。

### 11.2 分块、清单和不可覆盖

每次运行按年份保存一个证据块，单块目标不超过 5 MB。键名固定包含项目 ID、v2 版本、冻结 Git 提交、运行标签、回测 ID 和年份。另保存一份 manifest，列出所有块的键、字节数、SHA-256、首末日期和行数。

每个日度证据行至少包含：

- 策略权益与独立 SPY 总回报权益；
- 各模块当日 PnL、累计 PnL、费用和滑点；
- 所有非零持仓、现金、保证金和期权最大损失；
- 实际 gross、Alpha gross、Beta、风险贡献、回撤和回撤状态；
- 当前训练窗、选中参数组合和机械选择依据；
- 数据截止、信号、订单和成交时间；
- 数据许可、缺失、拒绝、部分成交、取消、行权、指派和门禁失败。

同一键已存在时正式运行必须失败，禁止覆盖。任一块或 manifest 保存、下载、哈希或日期连续性失败，整体状态为 `UNVERIFIED`。

## 12. 独立复算与归因

Atlas 的独立验证器不得导入云端策略的指标或评价实现。它从证据块和 QuantConnect 分页 API 重新计算：

- 每个执行折和自然年的策略、SPY、超额与 `SPY+10`；
- 拼接 walk-forward CAGR、正超额年份比例、Information Ratio 和最大回撤；
- 各模块日度 PnL、费用、滑点、边际贡献和移除模块后的组合结果；
- gross、Beta、风险贡献、保证金和期权最大损失峰值；
- 基础与双倍滑点的验收状态。

年度收益和最大回撤与云端统计的绝对差不得超过 `0.0001` 回报单位，即 `0.01` 个百分点。订单和成交必须完整分页，API 总数、证据总数和云端汇总必须一致。

组件验证固定包含：动态核心单独、股票单独、期货单独、防御期权单独、完整组合，以及每次移除一个模块的四组 ablation。只有完整组合用于正式目标；组件与 ablation 用于解释贡献，不能事后挑选最佳组合覆盖正式结果。

## 13. 错误处理和失败关闭

- 核心 SPY、已持仓证券或训练窗数据不完整：`UNVERIFIED` 并停止该折；
- 训练参数没有合格组合：下一折只运行风险管理后的 SPY 核心并记录固定失败代码；
- 股票借券或借券费不能按历史时点验证：在首次经济回测前固定使用预定回退结构；经济结果出现后禁止切换；
- 期货实际合约映射、carry 两端或交割缓冲不完整：该根合约在该信号周期目标为 0，并记录；覆盖不足使整个根合约在数据审计阶段排除；
- 正常 Option Chain 中没有合格价差：合法空仓；无法区分缺链和不合格：`UNVERIFIED`；
- Object Store、API 分页、哈希、独立复算或严格因果样本不足：整体 `UNVERIFIED`；
- 风险、保证金、裸腿、账本或未来数据违规：整体 `FAIL`；
- 云端编译、节点或 API 失败：不发布绩效结论，也不自动重跑覆盖。

## 14. 测试和云端验证

### 14.1 本地人工夹具

本地测试不下载历史行情，只用人工构造数据验证：

- 5 年训练和下一年执行的折边界，尤其闰年、首末共同交易日和 2026 部分年份；
- 27 个参数组合的固定搜索、淘汰、0.50 个百分点稳定区和确定性 tie-break；
- 未来数据追加不改变过去 Universe、因子、carry、参数选择、订单和权益；
- 行业、规模和 Beta 中性约束；
- 动态 Beta、10%/15% 回撤状态和恢复滞后；
- 快慢趋势、carry、实际合约换月和连续合约禁止下单；
- 期权条件、Delta 选腿、最大支出、年度预算、原子订单和退出；
- 2.00x total gross、0.80x Alpha gross、风险贡献、保证金和账本守恒；
- 证据分块、manifest、唯一键、哈希、缺块和不可覆盖；
- 独立 CAGR、年度超额、Information Ratio、最大回撤与门禁。

### 14.2 云端阶段门禁

1. Object Store capability smoke 必须先通过；
2. 数据审计固定借券结构和有效期货根合约，不读取经济结果；
3. 四个模块分别编译并运行短区间因果/订单 smoke；
4. 组件和 ablation 跑完整 walk-forward，保存完整证据；
5. 参数选择器机械产生每折参数；
6. 锁定 Git 提交后只运行一次完整组合基础成本和一次双倍滑点；
7. Atlas 下载并独立复算；
8. 无论 `PASS`、`FAIL` 或 `UNVERIFIED` 都归档并提交，禁止覆盖。

## 15. 交付物与阶段

### Phase A：证据与归因基础

- 新 v2 QuantConnect 项目；
- Object Store 权限/类型 smoke；
- 分年证据块、manifest、下载器和独立验证器；
- 日度模块 PnL 与 ablation 接口。

### Phase B：模块重建

- 动态 SPY 核心；
- 行业/规模/Beta 中性股票 Alpha；
- 快慢趋势加 carry 期货 Alpha；
- 定义风险防御期权；
- 每个模块的人工夹具、云端 smoke 和数据覆盖报告。

### Phase C：walk-forward 与组合

- 固定 27 组合优化调度；
- 独立机械选择器；
- 组合风险、成本和下一时点执行；
- 组件、ablation、基础和双倍滑点证据。

### Phase D：冻结评价

- 冻结规范、资产池、公式、参数范围、成本和风险上限；
- 提交不可变 Git 版本并验证云端源码一致；
- 运行一次基础成本和一次双倍滑点；
- 独立复算并发布中文报告；
- 保留所有失败运行和限制。

### Phase E：paper-forward

- 锁定 v2 后至少 6 个月只读 paper-forward；
- 不根据 paper 结果改写已发生信号；
- 任何 v2.1 假设使用新版本和新证据链；
- 本阶段不授权实盘或真实订单。

## 16. 明确不包含的范围

- 覆盖或删除 v1 结果；
- 以 2015–2026 为真正未见样本；
- 加密货币、单一历史赢家资产或事后选出的替代数据；
- 超过三个经济参数维度的云端历史寻优；
- 基于年度达标差距的追赶式加仓；
- 未建模借券费的个股做空；
- 裸期权、无限损失结构、税务优化；
- Webull、Robinhood、IBKR 或其他券商连接；
- 模拟盘、实盘、自动下单或部署上线。
